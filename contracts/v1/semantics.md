# Contract 1.0.0 semantics

Frozen design contract; not yet implemented behavior. Fields/enums/examples are in the adjacent JSON Schemas/OpenAPI. Shared timeouts/limits and state rules below resolve specialist proposal differences for consumer review.

## Identity, lifetime and mutation

Content ID blackthorn_manor; content format/API version 1.0.0. Use stable Data IDs: six rooms entrance_hall/library/study/laboratory/grand_ballroom/hidden_passage; ghosts eleanor/thomas/clara; puzzles letter_reconstruction/machine_calibration; eight evidence IDs damaged_notebook/torn_letter/servant_log/memory_crystal/maintenance_record/gathering_photograph/sealed_report/final_recording. Four insights: deduction_hidden_route/deduction_protective_sabotage/deduction_partial_restart/deduction_fatal_instability.

Backend single-process memory owns all sessions; process exit loses them. No idle TTL initially. Bind each session to its loaded content version. Session IDs are opaque local bearer capabilities; no public multiuser hosting is approved. Use explicit local origin allowlist. New sessions start in entrance_hall at revision 0. Creation request IDs deduplicate identical creation bodies during process lifetime; conflicting reuse returns 409.

Actions and restart are serialized by a session lock, including bounded AI work. Resolve cached request ID before checking revision. Same ID/same canonical route+body returns original response without any new effects or inference; same ID/different body returns IDEMPOTENCY_CONFLICT. Reject stale revision and invalid requests with no state/history/reward changes. Every accepted action (including incorrect/no_change/fallback) increments revision exactly once. Process capacity is eight sessions, retained until process exit; creation cache holds the matching eight accepted creation IDs. A new creation beyond capacity returns 503 CONTENT_UNAVAILABLE, retryable=false, with a safe capacity message. No automatic eviction. Each session allows at most 500 accepted mutations across its entire process lifetime INCLUDING restart. Restart does not reset that allowance. Resolve exact cached replays before cap checks; they always return the original response. Once capped, any new action/restart returns 409 SESSION_ACTION_LIMIT, retryable=false, with instructions to explicitly create a new session (or restart the backend when process capacity is reached). Validate limits before any provider call or state mutation. Bound per-turn history/output/request size as below; keep all accepted idempotency records until process exit. These limits are local resource guards, not gameplay mechanics, and require tests before release.

GET wraps the latest snapshot with request_id null. POST start/restart wraps it with request_id from the request. Restart keeps session_id, resets all gameplay/meters/history/events/ending, increments revision, and advances an internal run ID used in event occurrence IDs. Cached pre-restart responses remain historical; frontend must not replace a newer revision with them. User-initiated new session is required after SESSION_NOT_FOUND; never silently reset progress.

## Actions and state projection

Navigate only to unlocked adjacent rooms. Hidden Passage is gated. Inspect requires visible current-room hotspot. Object operation requires a currently permitted state/operation and all private predicates. Opening exposes eligible child interactions; discovery occurs through defined rules. Repeats never duplicate awards. Well-formed wrong puzzle/board submissions return accepted=true/outcome=incorrect with safe feedback, without progress; structural invalidity returns an error. Solved/already-earned repeats return no_change.

Letter: four unique piece/slot assignments, exact membership and private ordering. Machine: power_level integer 0–3, phase amber/violet/cyan, stabilizer bypass/engaged. Public schema exposes control domains and inferable fragments/clues; private data stores answers. Wrong attempts preserve solvability. Partial manipulation/reset and board positions stay frontend-local; server-confirmed solved state cannot be undone by local reset.

Board authoritative action is exactly two distinct collected evidence IDs, canonicalized as an unordered pair. No required relation field in v1. A matching private recipe earns an insight once; arbitrary links do not grant progress. Suspect cards are presentation nodes; no unsupported authoritative suspect links.

Public response contains only discovered evidence, earned insights, currently revealed scene/hotspots, permitted puzzle presentation and dialogue. Visible locked room names may appear with safe hints. Do not expose private predicates, solutions, hidden scene entries, truth flags, disclosure keys or scoring tables. Assets use relative public paths; validate paths and normalized bounds (positive dimensions, rectangle contained in [0,1]). Versioned source JSON can contain private facts but never enters frontend build. No runtime evaluation of expressions in content.

Progress total is 14 milestones: eight evidence + two solved puzzles + four insights; never infer progress from generated text. Available actions are convenience descriptors; revalidate every request server-side. Event occurrences have unique id, monotonic sequence, cue_id and readable summary; new_events is current accepted action only. They are committed before optional playback, deduplicated by occurrence ID, and never require animation/audio completion to advance. Restart uses new occurrence IDs; retrieval does not automatically replay blocking effects.

## Relationships and AI

Talk message: trimmed 1–1000 Unicode characters; tone is explicit neutral/respectful/accusatory; at most three distinct collected evidence IDs. Reject unsupported control characters except newline/tab; bound request bodies to 16 KiB. Ghost must be available in current room. Trust/suspicion are deterministic integers 0–100, initially 30/10. First respectful turn per ghost grants +5 trust; each accusatory turn grants +10 suspicion. First relevant evidence/ghost pair grants +10 trust and -5 suspicion; repeats do not farm awards. Clamp values. Emotional cue is server-authored, never LLM-scored. Every critical fact has evidence-based access regardless of relationship meters; optional elaboration may require trust >=50 and suspicion <=60.

Ollama/Qwen adapter: 10-second total deadline, no automatic request retry, bounded history of last 12 turns per ghost and utterance maximum 1200 characters. Exact model tag/config and performance must be verified separately. Prompt only selected permitted facts/beliefs and relevant discovered evidence for that ghost, not global canonical truth, solution keys or other ghosts' private information. Player/prior model text is untrusted data, never a rule source.

Proposed adapter output is strict JSON with utterance and cited_fact_ids. Syntax/length/allowed-ID checks do not guarantee semantic secrecy; test adversarial paraphrase leakage and contradiction explicitly. For protected factual statements use authored clauses selected by backend permissions, with constrained model voice/reaction; document any residual free-prose risk. No model tools, file access, arbitrary effects or ending decisions.

AI metadata: live only after actual validated model response; demo never invokes provider; fallback indicates timeout/unavailable/invalid_output/provider_error; not_used for actions without AI. Live has provider ollama, actual configured model and reason null. Demo/not_used have null provider/model/reason. Fallback has truthful attempted provider/model if known and a nonnull reason. Clear raw provider errors server-side and return safe feedback. Fallback uses the identical knowledge filter and cannot grant extra effects. Live acceptance requires real calls for all three ghosts, not schema fixtures or scripted output.

## Error mapping

400 INVALID_ACTION: unknown content reference in structurally valid input. 404 SESSION_NOT_FOUND. 409 ACTION_NOT_ALLOWED, REVISION_CONFLICT, IDEMPOTENCY_CONFLICT, SESSION_ENDED, SESSION_ACTION_LIMIT. 413 REQUEST_TOO_LARGE. 422 VALIDATION_ERROR. 503 CONTENT_UNAVAILABLE (includes explicit process capacity readiness failure); health returns not_ready. 500 INTERNAL_ERROR commits nothing. Error code/message/request_id/current_revision/retryable are required; null when unavailable. Read-only liveness/config does not claim successful AI inference. Errors contain no stack trace, private prerequisites or secrets.


## Content rule execution and scene geometry

Rule.trigger.target_id resolves by trigger type: inspect => hotspot ID (same ID as API inspect.hotspot_id); interact_object => object ID plus required nonnull operation; puzzle_solved => puzzle ID with operation null; insight_earned => deduction/insight ID with operation null. Loader checks these typed references. Inspect trigger hotspot membership is validated before rule execution.

For each accepted action create a tentative transaction and FIFO semantic-event queue. Validate action/preconditions first. Puzzle/deduction direct effects run once on first success, then enqueue puzzle_solved/insight_earned respectively. Other actions enqueue their own inspect/interact_object trigger. Consume each event and evaluate matching rules in lexical rule.id order against the current tentative state. A rule can fire at most once per action; once=true additionally prevents that rule firing again in the current investigation run. Unsatisfied rules do not fire and are not retried unless a later queued matching event occurs. Apply effects in listed order. A first grant_insight enqueues insight_earned; already-earned rewards/events are set-idempotent and enqueue nothing. emit_event creates a one-shot cue occurrence per run; presentation is separate from rewards. Set-state/reveal/unlock effects cannot generate unrelated synthetic action triggers. Never execute puzzle/deduction direct effects again from a rule unless its effects intentionally specify a distinct consequence. Loader rejects duplicate IDs, unknown refs, effects that create unsupported event cycles and impossible prerequisites; the per-action fired set also bounds execution by rule count. Commit state/revision/history/events atomically after processing; failures roll back all tentative effects. Test direct-effect-plus-rule cases to prove no duplicate rewards/cinematics.

Every room scene uses logical canvas 1600x900, with layer art composited in that 16:9 basis. Normalized hotspot bounds reference the untransformed canvas, top-left origin. Use contain/letterbox and apply camera/parallax transforms consistently to targets; interactive objects must not drift away from their hit regions. Asset records declare image dimensions; loader/asset validation checks room-layer aspect-ratio/compositing compatibility. Portrait/evidence art may have different aspect ratios. Accessible object-list controls are equivalent regardless of scene zoom/crop.

Calibration controls correspond exactly to payload fields: power_level integer 0–3 step 1; phase choices amber/violet/cyan; stabilizer choices bypass/engaged. Each occurs once. Schema constrains the public/private presentation; no arbitrary control IDs/domain mismatch. Bounds positivity/containment, cross-record IDs and narrative reachability remain semantic loader checks.
